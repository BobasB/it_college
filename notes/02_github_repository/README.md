# Початок роботи з GitHub та Markdown
> Репозиторій — це папка з проєктом, історія змін якої зберігається в Git та публікується на GitHub. Markdown — проста мова розмітки, якою оформлюються README та звіти.

## Мета роботи
Створити власний репозиторій на GitHub, клонувати його у VS Code, оформити `README.md` у форматі Markdown та навчитись робити коміти й відправляти зміни на GitHub.

## Що потрібно знати / підготувати
- виконана робота [«Налаштування робочого середовища»](../01_first_lesson/README.md): встановлені Git, Python, VS Code та створений акаунт GitHub;

---
### Створення репозиторію на GitHub
1. Для початку роботи всі повинні мати обліковий запис GitHub;
1. Створити GitHub репозиторій у браузері;
    1. Перейдіть у вкладку `Home` у лівому верхньому куті сайту [GitHub](https://github.com/)
    1. У браузері натиснути на кнопку `NEW`;
    1. Дати назву новому репозиторію;
    1. Репозиторій повинен бути публічним;
    1. Поставити галочку, щоб додати файл `Add a README file`;
1. Ознайомитися з новим репозиторієм та його меню. За бажанням можна внести зміни до файлу;

---
### Робота з Visual Studio Code
1. Створити робочу папку на комп'ютері, де зберігатимуться всі файли;
1. Відкрити цю папку через інтерфейс VS Code;
1. У вікні `Get Started` натиснути кнопку `Clone Git Repository...`;
    - вибрати копіювання репозиторію з GitHub;
    - програма попросить дозволу на продовження та відкриє веббраузер;
    - пройти авторизацію та дозволити інтеграцію між VS Code і GitHub;
1. Після налаштування інтеграції повернутися до вікна `Get Started` (якщо воно закрилося, відкрити меню `Help` -> `Get Started`);
1. Тепер після натискання кнопки `Clone Git Repository...` відобразиться список репозиторіїв. Обрати новостворений репозиторій та завантажити його на локальний комп'ютер;

---
### Робота з форматом MarkDown
1. [Короткі відомості про роботу з Markdown](https://github.com/adam-p/markdown-here/wiki/Markdown-Cheatsheet) або [документація Visual Studio Code щодо роботи з Markdown](https://code.visualstudio.com/docs/languages/markdown);
1. За бажанням можна використовувати смайлики, емоджі та піктограми під час написання тексту: [список](https://gist.github.com/rxaviers/7360908).
1. Створення/редагування першого файлу `README.md`;
    - внесіть зміни до файлу, вказавши:
        1. призначення цього репозиторію та те, що в ньому міститиметься;
        1. хто є власником репозиторію, де навчається власник і в якій він групі;
        1. як працювати з репозиторієм та Visual Studio Code;
        1. нумерований список майбутніх робіт;
        1. використовуючи AI/Copilot, сформулюйте запит для оформлення репозиторію. Опишіть, що ви хотіли б бачити на початковій сторінці. Використовуйте кнопку `Copy`, щоб зберегти правильно відформатований текст, згенерований AI/Copilot.
    - створіть ще одну папку `init` та додайте до неї новий файл `README.md`;
        1. поекспериментуйте з форматуванням Markdown та заповніть цей файл інформацією (будь-чим на власний вибір або сформулюйте запит до AI/Copilot, який створить таблицю із записами про лабораторні роботи чи нумерований список робіт);
        1. створіть декілька рівнів заголовків, спробуйте застосувати різні види форматування тексту, додати посилання на файли, картинки та інші можливості Markdown;

### Робота з GitHub комітами

> [!TIP]
> [Можна ознайомитися з основними командами для роботи з Git за посиланням](https://training.github.com/downloads/ua/github-git-cheat-sheet/);

1. Переконайтеся, що внесені до файлів зміни збережено (налаштуйте автоматичне збереження файлів: у лівому нижньому кутку є меню `Manage` -> `Settings` -> `Auto Save`);
1. На лівій панелі перейдіть на вкладку `Source Control`. У ній відображатимуться всі зміни, зроблені локально, але ще не завантажені до репозиторію;
1. (вкладка `Changes`) Файли можна додавати окремо, натискаючи символ **+** біля кожного зміненого файлу, або додати зміни в усіх файлах разом, натиснувши символ **+** для всієї вкладки;
1. (вкладка `Staged Changes`) Після додавання файлів їх можна завантажити до репозиторію за допомогою кнопки `Commit`. Перш ніж натиснути її, додайте короткий опис або повідомлення про те, що саме було змінено в цих файлах;

> [!TIP]
> Якщо на цьому етапі виникає помилка `make sure you configure username and email in git`, відкрийте термінал (вкладка `Terminal` -> `New Terminal`) та виконайте наведені нижче команди, попередньо вказавши свої ім'я користувача та адресу електронної пошти (копіюйте команди по одній):
> ```bash
> git config --global user.name "Your Name"
> ```
> ```bash
> git config --global user.email "youremail@example.com"
> ```

1. Після додавання файлів з'явиться нова кнопка `Sync Changes`. Натисніть її, щоб відправити файли до репозиторію;
1. Після успішного виконання цієї операції зміни буде завантажено до репозиторію. Перейдіть у веббраузер та переконайтеся, що зміни присутні в репозиторії;

### Те саме у терміналі (додатково)
Графічний інтерфейс VS Code виконує під капотом звичайні команди Git. Спробуйте їх у терміналі, знаходячись у папці репозиторію:
```bash
git status                      # які файли змінено
git add README.md               # додати файл до наступного коміту
git commit -m "Оновив README"   # зберегти зміни локально
git push                        # відправити коміти на GitHub
git log --oneline               # історія комітів
```
:star: Виконайте команди та вкажіть у звіті вивід `git log --oneline`.

> [!WARNING]
> Якщо `git push` повертає помилку авторизації, повторіть вхід у GitHub через VS Code (`Accounts` у лівому нижньому куті) або використайте Personal Access Token замість пароля.

### Що має бути у звіті
- посилання на створений репозиторій;
- скріншот гілки `main` із файлом `README.md` на GitHub;
- вміст `README.md` та `init/README.md` (або посилання на них);
- вивід `git log --oneline` з мінімум трьома комітами;
- висновок за [шаблоном](../../reports/README.md).

### Критерії оцінювання
| Рівень | Що потрібно виконати |
| --- | --- |
| Достатній | репозиторій створено, `README.md` оформлено, зміни відправлено на GitHub |
| Високий | + використано різні елементи Markdown (заголовки, списки, таблиці, посилання, зображення), мінімум 3 змістовні коміти |
| Відмінний | + виконано команди Git у терміналі, повідомлення комітів чіткі й змістовні |
