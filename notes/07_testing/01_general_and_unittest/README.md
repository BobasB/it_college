# Загальне тестування та юніт-тести
> Тестування перевіряє правильність роботи програми за підготовленими сценаріями. Юніт-тест перевіряє невелику самостійну частину коду.

## Перевірка даних
1. `assert` перевіряє твердження та зупиняє програму, якщо умова хибна:
    ```python
    number = -1
    assert number > 0, "Число має бути більшим за нуль!"
    ```
2. `raise ValueError` доречний, коли програма має повідомити про неправильний аргумент:
    ```python
    def create_name(name):
        if not name:
            raise ValueError("Ім'я не може бути порожнім")
        return name
    ```
3. :star: Створіть власну перевірку введеного числа та опишіть у звіті результат для правильного й неправильного введення.

## Тестування функцій
1. Юніт-тест можна написати для окремої функції. Спочатку визначте очікуваний результат для звичайних, порожніх і граничних даних:
    ```python
    def count_symbols(text: str) -> int:
        return len(text)
    ```
2. Перевірте функцію за допомогою `unittest`:
    ```python
    def test_count_symbols(self):
        self.assertEqual(3, count_symbols("abc"))
        self.assertEqual(0, count_symbols(""))
    ```
3. Перевіряйте не тільки правильні дані, а й помилки. Наприклад, для функції ділення потрібно перевірити `ZeroDivisionError`.
4. :star: Створіть функцію, яка рахує кількість голосних літер у рядку, і напишіть щонайменше три тести для неї.
5. :fire: Додайте тести для порожнього рядка, рядка з цифрами та рядка з українськими літерами.

## Життєвий цикл тесту
- `setUp` виконується перед кожним тестом;
- `tearDown` виконується після кожного тесту;
- `setUpClass` виконується один раз перед усіма тестами класу;
- `tearDownClass` виконується один раз після всіх тестів класу;
- кожен метод тесту має починатися з `test_`;
- тести мають бути незалежними та давати повторюваний результат.

## Розширені можливості unittest
1. `subTest` дозволяє перевірити кілька наборів даних і побачити, який саме набір не пройшов:
    ```python
    def test_figure_lengths(self):
        for length in [1, 5, 10]:
            with self.subTest(length=length):
                self.assertEqual(length, Figure("квадрат", length).get_figure_length)
    ```
2. `unittest.mock` замінює зовнішню залежність під час тесту. Наприклад, можна підмінити `input` і перевірити функцію без ручного введення:
    ```python
    from unittest.mock import patch

    @patch("builtins.input", return_value="5")
    def test_input(self, mock_input):
        self.assertEqual("5", input("Введіть число: "))
        mock_input.assert_called_once()
    ```
3. Mock потрібно використовувати для зовнішніх сервісів, часу, випадкових значень або введення користувача, а не для приховування помилок у власній логіці.
