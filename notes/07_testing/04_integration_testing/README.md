# Інтеграційне тестування
> Інтеграційний тест перевіряє взаємодію кількох частин програми: вебмаршруту, бізнес-логіки, бази даних і файлової системи.

## Мета роботи
У цій роботі потрібно протестувати невеликий Flask-застосунок. Користувач створює завдання через HTTP-запит, застосунок зберігає його в SQLite, а потім експортує список завдань у JSON-файл.

На відміну від юніт-тесту, тут ми не замінюємо базу даних і файлову систему mock-об'єктами. Тест використовує тимчасову папку та перевіряє повний сценарій від HTTP-запиту до збережених даних.

## Підготовка
1. Перейдіть до папки прикладу:
    ```bash
    cd example/testing/04_integration_testing
    ```
2. Встановіть Flask і pytest:
    ```bash
    pip install flask pytest
    # або
    poetry add --group dev flask pytest
    ```
3. Ознайомтеся з файлами `app.py` і `test_app.py`.

## Тестування файлів
1. Функція `export_tasks` записує завдання у JSON-файл.
2. У тесті використовується fixture `tmp_path`, яка створює тимчасову папку.
3. Після тесту тимчасові файли видаляються автоматично.
4. :star: Додайте перевірку порожнього списку та пошкодженого JSON-файла.

## Тестування бази даних
1. Функція `init_db` створює таблицю `tasks` у SQLite.
2. Тести використовують окрему тимчасову базу, тому не змінюють дані користувача.
3. Перевіряється не лише HTTP-відповідь, а й фактичний запис у таблиці SQLite.
4. :star: Додайте тест, який створює два завдання та перевіряє їх порядок у базі.

## Тестування вебзастосунку
1. Flask надає тестовий клієнт без запуску справжнього сервера:
    ```python
    response = client.post("/tasks", json={"title": "Вивчити pytest"})
    assert response.status_code == 201
    ```
2. Перевірте статуси `200`, `201` і `400` та вміст JSON-відповіді.
3. :star: Додайте тест для POST-запиту без поля `title`.
4. :fire: Додайте маршрут `DELETE /tasks/<int:task_id>` і інтеграційний тест, який перевіряє видалення запису з бази та JSON-файла.

## Запуск
```bash
pytest -v
pytest test_app.py::test_create_task -v
```

## Юніт-тест та інтеграційний тест
- юніт-тест перевіряє одну функцію ізольовано;
- інтеграційний тест перевіряє спільну роботу кількох компонентів;
- системний тест перевіряє програму майже так, як її використовує кінцевий користувач.

Не використовуйте робочу базу даних у тестах. Для кожного тесту створюйте тимчасові ресурси або окрему тестову базу.

### Звіт
- наведіть команду встановлення залежностей і запуску тестів;
- додайте результат виконання pytest;
- поясніть, які компоненти взаємодіють у кожному тесті;
- покажіть перевірки HTTP-відповіді, SQLite та JSON-файла.
