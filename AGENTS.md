# AGENTS.md

Інструкції для AI-агентів (Copilot, Claude, Codex тощо), які працюють у цьому репозиторії. Навчальний репозиторій Львівського ІТ Коледжу: лабораторні роботи, приклади та шаблон звіту з Python. Додаткові правила для Copilot: [.github/copilot-instructions.md](./.github/copilot-instructions.md).

## Мова та аудиторія
- Увесь студентський текст (README, інструкції, коментарі в навчальних прикладах) пишіть **українською**; команди й код — у блоках із вказаною мовою (` ```bash `, ` ```python `).
- Аудиторія — студенти-початківці. Явний код і малі зміни кращі за абстракції та рефакторинг.

## Структура репозиторію
| Шлях | Призначення |
| --- | --- |
| `notes/NN_*/README.md` | інструкції до лабораторних робіт (порядок — [notes/README.md](./notes/README.md)) |
| `notes/LAB_TEMPLATE.md` | шаблон нової лабораторної роботи |
| `example/` | робочі приклади, тести, ноутбуки, екзаменаційні завдання ([example/README.md](./example/README.md)) |
| `reports/` | шаблон звіту студента |
| `.github/workflows/` | CI: `coverage.yml` (тести `example/coverage_io` + Codecov), `manual.yml`; `cron.md` — вимкнений приклад |
| `_config.yml` | налаштування GitHub Pages (тема `midnight`) |

Нумерація папок у `notes/` історична (є два `05_*` та два `06_*`); порядок робіт задає `notes/README.md`. При додаванні/перейменуванні роботи оновіть цей список та посилання.

## Структура лабораторної роботи
Кожен `README.md` роботи має розділи (див. [LAB_TEMPLATE.md](./notes/LAB_TEMPLATE.md)): **Мета → Що потрібно знати → Хід роботи → Що має бути у звіті → Критерії оцінювання → Контрольні питання → Здача роботи**.
- Позначки: :star: — обов'язково вказати у звіті, :fire: — підвищена складність, `> [!WARNING]` — типова помилка.
- Кожен крок — одна дія з точною командою й очікуваним результатом.
- Посилання відносні, перевіряйте, що файли існують (особливо після перейменувань).
- Команди дайте для Windows і macOS/Linux, якщо вони відрізняються (наприклад, активація `venv`).

## Команди для перевірки змін
Запускайте з кореня репозиторію (Python 3.13+; CI використовує 3.10 для `example/coverage_io`).
```bash
# Тести запускаються з папки прикладу (в різних папках однакові app.py / test_app.py)
cd example/coverage_io && python -m pytest test.py -v
cd example/testing/01_general_and_unittest && python -m unittest -v
cd example/testing/02_pytest && python -m pytest -v
cd example/testing/03_coverage && python -m coverage run -m pytest && python -m coverage report -m
cd example/testing/04_integration_testing && python -m pytest -v     # потрібен flask
cd example/databases && python -m pytest -v
```
Потрібні пакети: `pytest`, `coverage`, `flask`. Не запускайте `pytest example/testing` одним викликом — буде `import file mismatch`.

Фрагменти коду з README перевіряйте запуском (код у списках має відступ — приберіть його перед запуском).

## Правила змін
- Робіть точкові зміни; не рефакторте навчальні приклади без потреби й не додавайте важких залежностей та нових фреймворків.
- **Навмисні помилки**: `example/coverage_io/app.py` (`get_figure_length` повертає `self.type`) і закоментований тест у `example/coverage_io/test.py` — частина завдання. Перш ніж «виправляти» код, прочитайте README відповідної роботи; якщо правите — додайте тест, який показує правильну поведінку.
- Виправляючи помилку в інструкції, перевірте команду на практиці.
- Ноутбуки (`.ipynb`): редагуйте окремі комірки; не форматуйте всі ноутбуки масово; у `notes/` зберігайте їх без виводів (outputs). Використовуйте сумісний із NumPy 2.x та сучасним Python код (`np.asmatrix`, а не `np.mat`).
- Не змінюйте завдання лабораторної на «вже виконане» — студенти мають виконувати їх самостійно.
- Не змінюйте CI (`.github/workflows`) і не додавайте залежності без погодження з викладачем.
- Тести мають бути детермінованими (фіксований `seed`, тимчасові папки `tmp_path`, база `:memory:`).

## Безпека та приватність
- **Ніколи** не комітьте `.env`, API-ключі (Google AI Studio тощо), `*.db`, віртуальні середовища, `__pycache__`, `.coverage`, `htmlcov/`, `.adk/`. Для ключів є `.env.example`.
- У прикладах використовуйте плейсхолдери (`your_api_key_here`); SQL-запити — лише з параметрами (`?`).
- Папки `my_first_agent/` та `demo/` навмисно в `.gitignore` (локальні експерименти з ключами) — не додавайте їх до коміту.

## Git
- Перед змінами виконайте `git status` та збережіть чужі незакомічені зміни.
- Коміти — короткі, зрозумілі (українською або англійською), одна логічна зміна на коміт. Не комітьте без запиту користувача. Для змін через PR працюйте у окремій гілці.
- У кінці commit-повідомлення, створеного агентом, додавайте trailer: `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`.
